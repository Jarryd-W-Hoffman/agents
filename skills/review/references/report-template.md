# Merged report template

Use this structure verbatim. Omit a severity section when it has no findings. Keep each finding to the fields shown; the reviewer's full evidence is available on request.

```markdown
# Four-pass review: {{TARGET_DESCRIPTION}}

**Verdict:** {{PASS | PASS_WITH_NOTES | REQUEST_CHANGES | FAIL | INCOMPLETE}}{{ — <pass> did not report | omit unless INCOMPLETE}}
**Scope:** {{N}} files, {{LINES}} changed lines ({{BASE}} → {{HEAD}}){{ · incremental since SINCE_REF | omit unless --since was used}}
**Passes:** completeness {{PASS|PASS_WITH_NOTES|REQUEST_CHANGES|FAIL|not run}} · correctness {{…}} · compliance {{…}} · consistency {{…}}
**Threshold:** {{THRESHOLD}} · **Verified:** {{K}} borderline findings checked, {{R}} refuted

## Critical ({{count}})

### [{{ID}}] {{title}}
`{{path}}:{{line}}` · confidence {{NN}} · {{pass}}{{, also raised by …}}
{{One or two sentences: what is wrong and why it matters.}}
**Fix:** {{concrete, minimal suggestion}}

## Major ({{count}})

### [{{ID}}] {{title}}
…

## Minor ({{count}})

- **[{{ID}}]** `{{path}}:{{line}}` — {{one-line description}} (confidence {{NN}}, {{pass}})

## Pass summaries

- **Completeness:** {{one sentence from the reviewer's Summary, or "not run" / "failed: reason"}}
- **Correctness:** {{…}}
- **Compliance:** {{one sentence; include the rule sources it consulted}}
- **Consistency:** {{…}}

## Notes

- {{Pre-existing issues, assumptions, deferred items the reviewers flagged; omit section if empty}}
```

## Rules

- Critical and major findings get a heading each. Minor findings are one bullet each.
- Sort within a section by confidence descending, then path.
- With `--since`, the scope line says so and names the ref. A reader must not mistake an incremental PASS for a verdict on the whole change.
- `INCOMPLETE` whenever a selected pass failed, errored or returned nothing usable — it outranks every other verdict, because a review that did not happen is not a clean one. Name the pass on the verdict line.
- The verdict line is computed, not judged: any critical → `FAIL`; else any major → `REQUEST_CHANGES`; else any minor → `PASS_WITH_NOTES`; else `PASS`.
- When posting to a PR (`--comment`), the header block and pass summaries become the review body, each finding becomes an inline comment, and the verdict sets the review event: `PASS` and `PASS_WITH_NOTES` approve, `REQUEST_CHANGES` and `FAIL` request changes. `scripts/post-review.py` appends the `Generated by four-pass-review (Claude Code)` footer itself.
- No emojis. No praise section unless the user asks for one.
